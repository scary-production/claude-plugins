# events — проверка

Файл для того, кто правит скилл: какие утверждения проверены и как их перепроверить.
Claude его не загружает.

## Сверено с документацией

| Утверждение | Раздел | Итог |
|---|---|---|
| `pg_try_advisory_lock` не ждёт и возвращает `false`; ключ — `bigint` или два `int4`; `_xact_`-вариант снимается в конце транзакции | PostgreSQL, Advisory Lock Functions | ✓ |
| Сессионный advisory-лок не подчиняется транзакциям: переживает rollback, снимается unlock или концом сессии | PostgreSQL, Explicit Locking → Advisory Locks | ✓ |
| Функция лока в запросе с `LIMIT` может взять лишние локи; надёжно — `LIMIT` в подзапросе | там же, пример с `LIMIT 100` | ✓ |
| Снимок `REPEATABLE READ` — с первой команды транзакции, `READ COMMITTED` — на каждую команду | PostgreSQL, Transaction Isolation | ✓ |
| Порядок Kafka — только внутри партиции; без коммита offset новые сообщения партиции ждут за упавшим | документация Kafka, разборы повторной обработки через retry-топики | ✓ потеря порядка при retry-топике — следствие, прямо не сказано |

## Проверено опытом

2026-10-22, PostgreSQL 18.6: psql в двух сеансах (таблица на 1000 сущностей, у 300 — по две
строки) и программа на Go 1.27.2 с pgx v5.11.0 и go-transaction-manager v2.0.4.

| Утверждение | Как проверено | Итог |
|---|---|---|
| Функция лока в `WHERE` рядом с `ORDER BY … LIMIT` берёт лишние локи | `LIMIT 10`, затем `pg_locks` своей транзакции | ✓ 10 строк, 1000 локов |
| Кандидаты подзапросом, лок снаружи — локов по числу строк | запрос из `relay-ordering.md` | ✓ 10 и 10 |
| `hashtextextended(text, bigint)` и `uuid_hash_extended(uuid, bigint)` есть и immutable | `pg_proc` | ✓ `provolatile = i` |
| В `REPEATABLE READ` второй запрос relay не видит пометок соседа, закоммиченных между снимком и локом | сосед держит лок и коммитит пометку, пока первый запрос стоит в `pg_sleep` | ✓ RC: 0 строк, RR: 2 — повторная отправка |
| Откат транзакции убирает и переход, и строку outbox | `Do` с записью сущности и outbox через транзакцию из ctx, затем ошибка | ✓ 0 и 0 |
| Запись outbox мимо транзакции из ctx откат переживает | то же, outbox — прямо через пул | ✓ перехода нет, строка outbox осталась |

## Не вошло

- Тест порядка relay (два воркера, одна сущность) и тест дедупликации inbox.
- Цифры: сколько хранить inbox, сколько попыток до DLQ, при каком размере таблица тормозит.
- Способ держать порядок в relay на аренде (короткая транзакция, доставка вне её).
- Инструменты, привязанные к одному брокеру (веб-админки топиков).
