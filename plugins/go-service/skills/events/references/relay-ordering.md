# Relay outbox в несколько воркеров: порядок внутри сущности

Блокируй **сущность, а не строку**. `FOR UPDATE SKIP LOCKED` по строкам раздаёт события одной
сущности разным воркерам, и позднее уходит раньше раннего.

## Рецепт

1. В транзакции relay первым запросом возьми неблокирующий лок по сущности. Занято
   (`false`) — сущность у другого воркера: пропусти её, не жди.

   ```sql
   SELECT c.entity_id
   FROM (SELECT entity_id FROM outbox
         WHERE processed_at IS NULL
         GROUP BY entity_id
         ORDER BY min(created_at)
         LIMIT $1) AS c
   WHERE pg_try_advisory_xact_lock(uuid_hash_extended(c.entity_id, 0));
   ```

   - Кандидатов выбирай подзапросом, лок вызывай снаружи. Функция лока в `WHERE` рядом с
     `ORDER BY … LIMIT` вычисляется для каждой строки до сортировки: на PostgreSQL 18
     `LIMIT 10` вернул 10 строк и оставил за транзакцией 1000 локов; с подзапросом — 10.
   - `ORDER BY min(created_at)` — старые сущности первыми. `DISTINCT … LIMIT` без порядка
     берёт произвольные, и часть сущностей может ждать долго.
   - Ключ лока — `bigint` или два `int4`. Хеш — `uuid_hash_extended(uuid, 0)` или
     `hashtextextended(text, 0)`: служебные функции хеш-индексов. В списке функций
     документации их нет, но они есть с PostgreSQL 11 и immutable, на них держится
     хеш-секционирование. Воркеры ходят в один сервер — нужна только согласованность.
     Коллизия хеша лишь лишний раз пропустит сущность на этом проходе.
2. Вторым запросом достань строки залоченных сущностей в порядке создания и отправь пачками,
   сгруппировав по топикам.
3. Отправилось — пометь пачку обработанной. Упало — не помечай: увеличь счётчик ошибок и
   запиши текст последней. Пачка помечается целиком, так что одно плохое сообщение задерживает
   соседей — это упрощение, разбор по сообщениям сложнее.

## Ловушки

- **Транзакция relay — `READ COMMITTED`** (по умолчанию). Второй запрос берёт свежий снимок и
  видит пометки соседа. В `REPEATABLE READ` снимок берётся с первого запроса: сосед закоммитил
  пачку между снимком и твоим локом — второй запрос увидит её неотправленной и отправит
  повторно.
- **Цена xact-лока** — транзакция открыта всё время отправки в брокер. Альтернатива —
  сессионный `pg_try_advisory_lock` на **одном** соединении (в pgxpool — `Acquire`) с явным
  `pg_advisory_unlock`. Сессионный лок не подчиняется транзакциям: переживает rollback и
  снимается только unlock или концом сессии. Взял лок одним запросом из пула, а читаешь
  другим — это может быть другое соединение: лок повиснет, а защиты не будет.
- **Дубли relay даёт всё равно**: непомеченная пачка уйдёт повторно. Получатель обязан их
  переживать.
- **Relay на аренде** (строку берут с `next_attempt_at` в будущем короткой транзакцией и
  доставляют вне её) этот рецепт не покрывает: xact-лок держится только пока открыта
  транзакция. Там нужен свой способ исключить вторую строку той же сущности.
